# 回包分析与持续探索

用途：接到目标、原始请求或 401/403/WAF 回包后，获取足以选择实验的信息并开始执行。已经有可靠现场时直接复用，不额外做整套侦察。

## 先提取事实

保存原请求、原响应、发送方式与实际连接条件。分别提取状态与头部、原始实体字节和可可靠解码的业务内容；分块、压缩、字符集或截断情况单独标记。工具摘要与实际返回包互相核对，解析出的事实不自动证明某个产品或漏洞。

| 信息 | 具体观察 | 如何影响下一步 |
| --- | --- | --- |
| 状态与认证挑战 | 状态行；401 的 `WWW-Authenticate`；407 的代理认证；403 的错误文本 | 区分凭据缺失、代理拒绝、应用拒绝；缺少标准头也保留实际响应 |
| 跳转 | `Location`、每跳状态、登录地址、跳转后方法和会话 | 判断是否仅跳到登录页、公开页或另一来源 |
| 身份与会话 | Cookie 名称、属性、实际请求携带的材料、是否有失效提示 | 复用正确会话并设置无会话/受限会话对照；不展示凭据值 |
| 边缘与代理 | `Via`、`CF-Ray`、`X-Amz-Cf-Id`、`X-Cache`、其他追踪字段、错误模板 | 提供路径和组件候选，结合正常页与日志判断；单头不确认拒绝来源 |
| 缓存 | `Age`、`Cache-Control`、`Vary`、ETag、条件请求与缓存命中字段 | 防止把旧缓存、公开缓存或 304 误当本次访问成功 |
| 路由与业务 | Content-Type、HTML 标题、JSON 错误码、字段、受控资源标识、默认站点特征 | 区分真正业务响应、默认虚拟主机和包装成 200 的拒绝页 |
| 解析入口 | 400/405/415、`Allow`、格式/字段/字符集错误、multipart 提示 | 选择方法、媒体类型、编码或参数位置的对照 |
| 连接条件 | DNS A/AAAA/CNAME、连接 IP/端口、TLS 证书/SNI、协商协议 | 选择域名/IP、Host/SNI、IPv4/IPv6或协议差异实验 |
| 时间与完整性 | 连接、TLS、首字节、总耗时，超时阶段、截断、解码失败 | 区分无 HTTP 回包与 HTTP 拒绝，避免把不完整正文用于相似度判断 |

RFC 语义、缓存及厂商响应信息提供参考 [R1–R3]。实际产品可以自定义错误页，应用也可能使用非标准状态；以观测和对照判断。

## 推断技术栈，用于调整候选优先级

组合正常页、拒绝页、头部、Cookie 名称、路径形态、页面源码和受控错误响应推断。只凭厂商模板或单一头部不能确定源站栈；可隐藏或改写的标识与运行版本分开记录 [R5–R6]。

| 观察到的线索组合 | 可保留的栈/链路候选 | 怎样影响实验 |
| --- | --- | --- |
| Server/错误页带 Web 服务器名称，但正常业务还出现其他框架线索 | 入口服务器与业务运行时可能不同 | 把入口路径匹配、rewrite 与业务 parser 分开研究 |
| `.jsp`、Java 风格错误或会话线索互相支持 | Java 容器/应用候选 | 先验证路径/Body 解析入口；Ghost 等特殊机制需具体调用证据 |
| `.aspx`、`__VIEWSTATE` 等线索 | ASP.NET 等候选 | 优先理解已有路由、会话与方法处理，不能假定当前容器版本 |
| `.php`、框架 Cookie 或源代码标记 | PHP/对应应用框架候选 | 从实际参数取值、form/JSON 入口和已暴露端点选择对照 |
| JSON 解析错误或可识别 parser 调用信息 | 对应 JSON 入口候选 | 先用合法转义/结构验证最终字段，再研究实现特有差异 |
| 追踪头、CDN 模板与正常业务响应明显不同 | 边缘拒绝与应用响应可能来自不同层 | 对比同站正常请求、受控不存在路径和范围内已知入口 |

推断的作用是减少无关实验，不是制造确定版本或自动选择 CVE。即使没有识别出框架，仍可进行一般的路由、参数、身份和表示对照。

## 从现场发现请求入口

优先利用用户给的流量、公开页面、JS 中的 fetch/XHR/API 地址、表单 action、重定向和已授权的接口文档，建立与目标问题有关的端点和请求形状。需要时查看资源引用、robots 或页面明确暴露的其他入口；不先扫一套猜测目录。

读取目标 DNS、配置中的 upstream/源站、部署记录和允许使用的历史记录，可以形成连接候选。证书 SAN、关联域名或同一 IP 只表示关联线索，不自动确认同一业务与测试范围。新候选按 [连接与入口](connection-routing.md) 核对。

## 持续展开请求与对照

下面是可持续展开的方向，按实际覆盖与反馈分配轮次。原协议、身份和业务条件，以及刻意改变的因素分别记录；相同候选可以反复执行，不把表格做完一遍或连续几个拒绝响应当作研究完成。

| 探针 | 想区分什么 | 有意义的观测 | 常见误判 |
| --- | --- | --- | --- |
| 原请求复发 | 基线稳定还是会话/状态漂移 | 相同拒绝类型、业务字段和缓存状态是否稳定 | 一次变化就宣布成功 |
| 已知可正常访问的同站端点 | 全站入口拒绝还是特定路径/内容拒绝 | 普通页也被同模板拒绝，或能进入业务层 | 默认页能访问等于受限资源能访问 |
| 随机受控不存在路径 | 拒绝是否发生在业务路由之前 | 与原请求同拒绝模板，或出现可识别业务 404 | 隐藏路由/应用 catch-all 也可能返回同页 |
| 现有请求换为无敏感值的同结构版本 | 拦的是内容还是路径/身份/格式 | 只有相关值变化时拒绝消失且业务格式可接受 | 删除必填字段导致另一种错误不是有效对照 |
| 合适的 HEAD 或 OPTIONS | 方法是否到达另一处理入口 | `Allow`、响应头、状态和 handler 线索 | HEAD 没 Body 很正常；OPTIONS 常由代理单独回答 |
| 受控的路径尾部或分隔变化 | 入口与后端是否规范化不同 | 同一受控资源出现不同准入结果 | 改变了资源或只命中静态默认页 |
| 保持 Host/SNI、连接已知授权 IP | 连接入口差异还是应用本身拒绝 | 相同资源在不同入口有可比业务结果 | 改成 IP URL 同时改变虚拟主机和 TLS |
| 已知正常浏览器请求与工具请求对照 | 会话/CSRF/客户端条件还是输入规则 | 正确会话下是否仍有相同内容拒绝 | 复制合法身份后成功属于正常访问 |

不存在路径和只读样本采用无副作用标记，例如 `/__probe_missing_7d3` 或原字段内的 `probe_A7`。写请求是否可复发由实际动作决定，避免触发真实支付、删除或重复任务。

## 从差异建立服务端假设

| 差异组合 | 当前候选解释 | 下一项判别实验 |
| --- | --- | --- |
| 正常页、不存在路径和受限路径均同模板 403 | 入口策略、默认虚拟主机或统一拒绝 | 检查 Host/SNI；比较已知入口；结合追踪日志 |
| 正常页进入业务，只特定值被拒绝 | 内容规则或业务值校验 | 保持结构和语义，局部编码/位置/大小写对照 |
| 只某一路径 401，挑战信息稳定 | 路由级认证或应用认证 | 方法/规范化/已有别名入口；同一受限身份复核 |
| 改格式后由拦截页变 415 | 到达了不同格式校验，或入口对格式有分流 | 找业务确实接受的表示，确认字段恢复 |
| 改方法后 405，`Allow` 有变化 | 路由或方法入口存在差异 | 对已知允许且可控的方法作业务验证 |
| IP URL 返回另一标题/证书/默认页 | 虚拟主机或 TLS 条件改变 | 使用域名 URL 与连接映射，维持 Host/SNI |
| 只有某一入口、端口或地址族出现业务响应 | 入口保护不一致或路由不同 | 确认同一业务、身份、资源，核对授权范围 |
| Cookie 恢复后正常，敏感值仍正常 | 原失败可能是会话/客户端条件 | 做同身份下的内容对照，避免误归为 WAF 绕过 |

这些是待验证解释。根据新信息保留、修正或淘汰，允许提出其他解释；不能仅靠模板猜定后端语言或版本。

## 把判断落实为请求与回包

选择当前环境已有的 HTTP 工具、浏览器或原始请求能力。工具至少能保留响应头和错误 Body、确认实际目标、控制跳转，并支持本次实验要保持的请求条件；字节敏感时核查请求是否被重编码或规范化 [R4]。

发送前明确三件事：当前假设、这次刻意改变的因素，以及不同结果将如何改变判断。原请求为 POST 等时保留原方法与实体语义，不能默认改为 GET；需要换方法时把方法作为实验变量。凭据按当前会话约定处理，分享证据时省略其值。

返回后同时读取状态/头部与业务内容。没有 HTTP 回包先定位 DNS、连接、TLS 或工具失败；有错误响应也保留完整 Body；出现跳转先保留原始 3xx 和 Location，再按任务范围决定是否继续。发现有意义的变化，先验证是否仍为原资源和原身份的结果。

各轮执行留下：请求及变化、连接条件、事实摘要、候选与复发次数、哪些解释受支持、哪些仍未知和下一轮覆盖。保持动作和反馈连接，不用一轮长答案代替多轮生成，也不用一轮少数请求代替持续实际尝试。

## 回包之后继续什么

把本次观测更新到候选队列，同时保留其他尚未完成的方向。下面是下一步选择示例，不是状态码对应的固定流程：

| 本次观测 | 后续工作 |
| --- | --- |
| 工具报错、连接失败或响应不完整 | 核查失败阶段与实际发送记录，用现有能力恢复或替换；未到达目标不算技术负结果，已发送无完整回包保留处理结果未知，状态性重试按实际可重复性处理 |
| 同一拒绝模板持续出现 | 保留本条件内的负结果，核对基线/身份/入口，并继续其他位置、表示、必要组合和复验；不宣称整类已排除 |
| 新的格式、字段或字符集错误 | 检查实际实体、声明与业务接收条件；保留原候选，构造可判别的表示与对照，不能仅凭错误模板推断真实解析器 |
| 方法或 handler 线索改变 | 比较最终方法、路由、身份和业务结果，展开相应候选；OPTIONS/HEAD 放行不能替代受限动作证据 |
| 状态成功但业务对象不符 | 核对默认站点、公开/登录页、跳转、缓存和会话变化；继续寻找原边界证据 |
| 原受限业务结果出现 | 固化请求/响应及条件，反复验证并排除替代解释，再按目标缩减或扩展适用范围 |
| 结果偶发变化或不同发送器结果不一 | 保存各次条件和实际字节，交错复发基线与候选，研究状态、传输与解析因素 |

分析与派发持续连接；未知栈不阻止已有适用候选，初步猜到服务端也不停止技术覆盖。不能要求先拿到源码、日志或完整产品指纹才继续黑盒验证。

## 从反馈展开后续轮次的示例

- 正常页和受控不存在路径能到业务层，只有原 Body 值被 403：比较无敏感值的同结构请求，持续展开编码、参数表示与必要组合；若转换后是 415，把实体、声明和接收条件列为下一轮变量，不据此判定整类编码失败。
- 同站公开资源正常，受限路径稳定 401 并带认证挑战：核对会话与预期角色；有依据时选择路径规范化、已发现别名、方法或 URL 覆盖对照。补齐合法凭据后成功只说明正常访问条件恢复。
- 域名入口统一拒绝，已知授权 IP 返回 200：先判断是否只是默认虚拟主机，再维持原 Host/SNI 与业务请求对照；相同受控资源在另一入口接受，才继续确认入口保护差异。

这些是根据观测展开尝试的例子，不要求复用其顺序。新反馈无法由现有解释覆盖时继续提出候选；反馈暂时一致时仍可扩展表示、入口与条件并重复关键请求。保留全部有效尝试，不能用模型认为“服务端已经猜清楚”作为停止依据。
