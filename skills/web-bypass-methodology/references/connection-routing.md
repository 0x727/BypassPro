# 连接、域名与入口差异

用途：域名被拦、IP 可达、CDN/WAF 拒绝、源站直连、虚拟主机或协议入口差异。先说明当前改变的是连接位置、TLS 名称、HTTP authority、身份还是业务路由。

## 把连接变量分开

记录：URL 中的主机与端口、实际连接 IP/端口、代理/出口、TLS SNI、HTTP Host 或 HTTP/2 authority、协议、请求路径、认证材料。Host 头不是 TCP 目的地址；HTTPS 中只改 Host 并不能保证 SNI 同步改变 [C1]。

| 对照方式 | 连接目标 | TLS SNI / 证书名称 | HTTP Host / authority | 主要判断 |
| --- | --- | --- | --- | --- |
| 原始域名 URL | 当前解析或代理选出的地址 | 原域名 | 原域名 | 基线 |
| 域名 URL + 名称到地址映射 | 指定已授权 IP，原服务端口 | 保持原域名 | 保持原域名 | 地址/入口变化下，同一虚拟主机是否受相同保护 |
| 域名 URL + 连接端点映射 | 指定已授权连接主机/端口 | 按原 URL 保持 | 按原 URL 保持 | 不同监听入口的保护与服务一致性 |
| HTTP IP URL + 原 Host | 指定 IP | 没有 TLS | 原域名 | 仅在 HTTP 本就在范围内时验证明文入口与虚拟主机 |
| HTTPS IP URL + 原 Host | 指定 IP | 按 IP URL，不能假定为原域名 | 原域名 | 用于判别默认 TLS/虚拟主机；不等价于正确源站直连 |
| 已知别名域名 URL | 别名当前地址 | 别名 | 别名 | 是否确为同一业务，且入口策略不同 |
| 同域名 IPv4 / IPv6 对照 | 已知 A / AAAA 地址 | 原域名 | 原域名 | 地址族入口是否一致，或只是网络可达性不同 |

这些变量可由具备连接映射能力的工具分别控制，curl 的实现可作为语义参考 [C1–C2]，不要求使用该工具。使用代理时映射与 DNS 可能由代理决定，必须检查实际 peer 和链路；要研究直连时明确选择允许的直连路径，不把工具选项当作已经切换成功。

## 域名被拦时先定位失败阶段

- DNS 失败：比较已有解析信息和已授权地址映射，保存解析错误。映射后连通仅说明该连接方式可达。
- TCP 失败：记录目标地址、端口、出口和连接错误；换为范围内已知入口作对照，不能将无 HTTP 回包叫做 403。
- TLS 失败：核查 SNI、证书名称、信任链、客户端证书和协议。SNI/Host 不一致可能触发拒绝 [C3]。
- HTTP 400/403/421：用原域名的正确 Host/SNI 与原请求对照，检查边缘规则、虚拟主机和应用拒绝。
- HTTP 200：确认是否恢复原受限资源和业务语义，还是只进入 IP 默认站点、公开页或登录页。

DNS、网络和 TLS 不可达，与 WAF 内容检测和应用鉴权是不同问题。任务明确包含可达性恢复时可以交付该结果；进一步边界失败仍需业务证据。

## 已知源站与替代入口

优先使用用户提供的源站、部署配置、DNS/历史记录及业务公开暴露的地址。关联证书、域名或 IP 只是候选。只有候选入口处于现有授权范围才连接；没有依据时先记录材料缺口，不能自动扩大到整个地址段或新组织资产。

在已知源站上保持原 Host/SNI、路径与测试身份，对比正常业务样本和受限请求。边缘拒绝而同一业务在源站接受，可支持“入口保护不一致”的候选；是否构成所研究的策略失败，取决于源站本应接受哪些来源及业务结果。

源站可能设置来源 IP 限制、mTLS、有效凭据或只通过隧道暴露 [C4–C5]。证书认证失败或连接拒绝是有效观测，不能把这些前提绕过假定为自动拥有的能力。

## 把入口假设转换成对照

以同一受控路径、同一测试身份和原始业务语义为基准，选择需要的对照。下面的域名和地址是文档占位值，次数和顺序按现场信息选择：

| 对照 | 保持的条件 | 刻意改变的条件 | 要求的判别证据 |
| --- | --- | --- | --- |
| 原域名基线 | `app.example.invalid` 的原 Host、SNI、方法、路径、会话与实体 | 无 | 记录当前连接地址、拒绝类型和业务字段 |
| 已知 IP 的同虚拟主机 | 原 URL、Host、SNI、协议及请求条件 | 连接到范围内 `192.0.2.10`，服务端口保持 | 确认实际 peer 变化且仍访问同一业务 |
| 已知其他监听入口 | 原 URL 的服务身份与请求条件 | 范围内已经存在的连接主机/端口 | 确认监听入口确为同业务，比较相同保护要求 |
| IP 默认站点判别 | 已知授权 IP、可控路径与请求成本 | 用 IP 作为 URL 名称，明确 Host/SNI 是否随之改变 | 标题、证书、路由或业务标识是否表明进入另一站点 |
| 明文入口对照 | 受控业务语义与明确记录的 Host | 仅在 HTTP 属于本任务时改变协议与对应端口 | 这是另一入口对照，不能把同时改变的变量归因于单一原因 |

保持证书身份验证和跳转行为可追溯。源站采用用户提供的私有 CA 时使用对应信任材料并记录条件；临时放宽校验的诊断结果不能单独证明服务身份。原会话与 Body 同样需要保持，不向范围外新来源复制凭据。

## 其他可选入口差异

| 可展开的方向 | 候选实验 | 成立条件或反例 |
| --- | --- | --- |
| 域名别名、大小写、尾点、IDNA/Unicode 表示 | 用实际已知别名或受控名称表示作单项对照 | 客户端、DNS、证书或虚拟主机可能改变；需确认同业务 |
| Host 中是否带端口 | 对照 `app.example.invalid` 与其真实服务端口表示 | 只在解析与规则可能不一致时测试；默认站点变化不证明绕过 |
| HTTP/HTTPS 或已知服务端口 | 连接范围内已经存在的入口 | 需要正确协议和身份；不要由此开展全端口扫描 |
| 转发 Host/Proto 元数据 | 比较已有字段的取值、来源和覆盖顺序，可作单项或有依据的组合对照 | 是否参与路由或鉴权、是否来自可信代理均需目标证据；客户端声明本身不建立信任 |
| HTTP/1.1 与 HTTP/2 | 用工具支持的协议维持同一请求条件 | 记录实际协商版本、authority 和响应；不同协议未必到同一处理栈 |
| URL 字段中的 IP/主机表示 | 用受控目标比较规范点分 IPv4、单整数/hex/前导零解释、IPv6/映射、userinfo 或编码 authority 等有线索的表示 | 只在任务确实涉及 URL 校验/后端请求时展开；接受方式由实际 parser 验证，不自动请求内网或云元数据 |

线索与支持条件用于排列和解释实验，未知条件也可进入范围内的候选。单项对照便于归因，不限制组合、覆盖轮次或原请求复验。
