# 对照实验与可复核证据

持续多轮推导和反复实际验证是默认策略，下面的方法用于组织覆盖、控制条件和记录证据。轮次数量与具体对照由任务约定决定；模型认为某问题简单、没有新想法或成功可能性低，不自动缩减绕过研究的轮次。

## 选择下一步与保留研究状态

每轮找出最影响结论的未知，并选择能减少该未知的动作。下面是选择示例，实际问题可以有其他切入点：

| 当前缺口 | 可选择的动作 | 怎样判断进展 |
| --- | --- | --- |
| 现场或拦截来源不清 | 读取已有证据，或在范围内作低成本探针 | 减少链路、身份或执行条件的未知 |
| 已有观测缺少解释 | 从原始材料再次生成候选 | 形成可区分的预测或发现遗漏前提 |
| 多个解释预测相同现象 | 设计最小判别对照 | 观测能支持、削弱或排除其中的解释 |
| 候选机制前提未知 | 检查调用入口或作条件探针 | 判断前提是否成立，并记录观测范围 |
| 业务边界失败已确认、根因未知 | 固化业务证据，再按任务需要定位机制 | 已确认行为不因根因未知而丢失 |
| 推导停滞 | 检查共享前提，再次生成、展开未覆盖条件或复发关键候选 | 增加实际覆盖和观测，不因短期停滞自动交付 |

已有候选、尚未解释的异常和其他适用方向在多轮中都保留验证机会。可以排列尝试顺序，但排序不能变成仅凭模型概率永久剪枝；模型熟悉度、历史案例和重复出现次数都不能证明某方向应该独占额度。

研究状态可记在上下文或当前任务文件中，规模以便于继续工作为准：每个候选保留机制、未知前提、证据指向、下一项判别实验，以及待验证、受支持、条件内未复现或被排除的状态。排除记录写清输入、环境、观测有效性与适用范围。

继续旧任务时先核对现场是否改变，复用已有字节证据、对照和范围内结论。隔离生成新的候选时可以暂不提供旧解释；汇合后查历史记录，并区分候选描述重复与计划内复发。已有失败记录保留条件和次数，不自动禁止后续复发或表示变化。新证据可以修正原先认定的事实与排除结论。

## 建立目标对应的对照

优先保留原始字节、响应、连接目标、身份和时间。原请求属于历史记录时，确认当前会话仍能重现原来的允许或拒绝状态。

| 问题 | 有信息价值的对照 | 能避免的误判 |
| --- | --- | --- |
| 基线是否稳定 | 按现场需要复发原请求，观察会话、缓存和动态内容 | 把自然波动误认为变体效果 |
| 访问控制是否失效 | 受控资源的预期允许身份、预期拒绝身份与候选受限身份 | 把正常登录、公开资源或账户切换误认为越权 |
| WAF 是否放行原语义 | 已有被拦截请求、业务可接受的正常请求和候选请求，结合处理证据 | 把语义破坏或进入错误解析器误认为绕过 |
| 某个操作是否必要 | 候选与移除该操作、移除触发点或替换局部条件后的请求 | 把组合中的无关字符当成关键技巧 |
| 发送器是否改变结果 | 相同候选在可比连接条件下的字节与处理记录 | 把网络路径、TLS、会话或协议变化误归因于编码 |

没有允许身份、后端日志或解析源码时仍可研究；用可获得的受控资源和业务证据补足。无法判别的部分保留未知，不编造未取得的正常样本或宣称已确定内部实现。

写操作、上传、触发任务等可能改变状态的实验，在任务允许范围内选择可控、可回收对象。一次普通 GET 也可能有业务副作用，是否可重复由实际动作和约束决定。

## 候选状态与持续派发

候选队列用来保存未完成动作与证据，不要求固定文件或字段格式。可以在上下文维护；跨轮次时保留足够继续工作的记录。

| 状态 | 当前含义 | 继续推进的动作 |
| --- | --- | --- |
| 待执行 | 已有候选，部分前提仍未知 | 构造实际请求与必要对照，在范围和资源内执行 |
| 已执行待判定 | 已发送，但响应、入口或业务观测不足 | 修复观测、复发或取得补充证据；不记作机制失败 |
| 条件内未复现 | 可比有效尝试未观察到预期结果 | 保存输入、条件和次数，继续其他表示/位置/组合或计划复验 |
| 有业务信号待复验 | 出现与目标相关的响应或行为 | 保留完整证据，重复验证并检查替代解释 |
| 已确认 | 当前结论层次已有充分目标证据 | 按目标复核范围、缩减或继续其他未完成方向 |
| 证据排除的条件 | 实际证据否定候选在特定条件下的断言 | 写清范围；新条件或冲突证据出现时重新评估 |

没有单独的“模型觉得不值得”淘汰状态。工具失败、越界、无法构造与有效请求未命中分别记录；技术索引中的未知前提不能被自动填写为不适用。

每次真实发送的请求、连接条件、响应、时间、所属候选和轮次配对；复发与重定向逐次计数。更新队列后继续已有动作，不等新想法出现才推进。只要仍在当前任务与资源范围内，阶段报告不结束派发。

## 让候选与对照回答清楚的问题

记录假设、作用位置、输入输出关系和预期观测，再生成候选。单因素对照方便归因；有处理链路依据时可以直接测试组合，不要求各单项先成功。组合仍要保留其实际字节、中间态、未知条件以及可区分作用的对照。

随各轮执行持续扩大适用方向、承载位置、表示和有依据的组合覆盖，信息获取与尝试共同推进。记录已覆盖和未覆盖的条件；模型自评“这一类应该无效”不能代替实际尝试。组合应保持可控语义与范围，不要求机械完成全部笛卡尔积。

候选描述可以按请求字节、连接目标和执行条件合并，但实际发送次数与各次观测单独保存。相同字节可以按复发计划反复执行；不同身份、协议或状态的相同字节属于不同条件。模型下等价的不同字节，也可继续用于字面量检测与归一化行为对照。

## 重复推导与重复验证

默认增加生成轮数与实际尝试，以下方式在持续研究中交替或组合使用。次数不由模型一次自评“已经充分”决定：

| 重复方式 | 保持什么 | 重看或改变什么 | 有价值的产出 |
| --- | --- | --- | --- |
| 再次生成候选 | 原始事实、目标和约束 | 从事实重新考虑尚未证实的解释，尽量减少首轮答案的引导 | 新机制、遗漏条件或可区分的预测 |
| 改换观察角度 | 同一问题和证据范围 | 例如从实际资源使用反看入口决策，或从字节反看编辑器表示；角度应有现场依据 | 揭示此前未考虑的链路关系 |
| 底层再推导 | 原始材料、边界目标与已验证条件 | 从最终结果反推输入，重看转换次序、类型/单位、检查范围、错误分支、信任或状态 | 派生不同操作、输入表示和组合，形成可验证的未知关系 |
| 反证检查 | 当前候选及其声称的证据 | 寻找替代解释、缺失箭头、违反前提的地方和最小反例 | 淘汰或修正候选，形成判别实验 |
| 重复目标验证 | 需要复核的请求、身份、资源及执行条件 | 控制时间、状态或必要局部条件，记录每次真实观测 | 复现稳定性、条件依赖或对照证据 |

前几类可以离线进行，最后一类记录真实请求和回包。持续重复分别遵守已有推导资源和目标执行约定；没有新想法时仍可再次生成、改变表示或按计划复发，不要求新增机制才继续执行。

底层推导使用 [第一性原理与机制推导](mechanisms.md) 的局部契约与可判别关系。推理深度不作发包门槛，也不以新增术语作为进展；把实际条件与观测接回队列，持续多轮展开和复验。

环境支持独立模型调用或隔离上下文时，可让新的推导只接收目标、约束、原始材料及必要的已验证事实，候选形成后再对照旧结果。输入输出和轮次要能追溯；汇合时使用研究状态核对已完成的验证和排除范围。

同一上下文中重新审视问题仍然有用，但与隔离调用分开记录。一次回答列出多个假设，也不能声称完成了多次独立采样。不要声称执行过未实际发生的调用、模型切换或采样参数调整；本方法不依赖特定模型、温度或多代理能力。

汇合候选时，按“机制与前提 → 预测 → 判别实验”比较。合并实质相同的候选，保留能导致不同决策的分歧。先判断解释能否覆盖关键观测，再比较额外假设与验证成本；多轮重复出现的解释不因此获得优先权。

重复出现的论断保留原来的证据等级。上一轮输出不能作为下一轮的新事实，多轮意见一致不能替代目标观测；共享输入或已有结论可能让多个样本产生相同偏差。

记录本轮生成了哪些候选、执行了哪些条件、复发了几次，以及真实反馈。换词或重写答案不算执行轮次；同方向的再次生成、不同字符/表示和相同请求复发，可以积累实际覆盖与重复观测。候选趋同先核查共同前提和观察角度，之后继续展开未覆盖条件或执行复发，趋同本身不构成停止证据。

推导轮次、方向覆盖和目标复发分别安排额度；用户已经给定的时间、次数与资源限制优先。已授权且未指定数字时，主动安排可说明的多轮额度，覆盖再次生成、不同适用方向、关键候选复发和反向核查；不能自行采用首轮少数尝试的默认总上限，也不把缺少数字本身当作阻塞理由。增加总轮次与增加并发分别管理。

## 轮次、覆盖与复发记录

开始研究时记录可调整的轮次目标和资源约定，执行中持续更新。没有一套适用于所有目标的固定次数；缺少固定数字不等于可以一轮即停。

| 记录维度 | 需要保留的事实 |
| --- | --- |
| 模型生成 | 计划与实际轮次、每轮输入依据、独立调用或同上下文重审、形成的候选 |
| 条件覆盖 | 入口、身份、方法、承载位置、表示、必要组合的已测与未测范围 |
| 实际验证 | 累计发送、有效/未判定尝试、每个候选复发次数、命中与未命中记录 |
| 任务推进 | 未完成的方向、下一轮安排、剩余时间/调用/请求额度 |
| 完成或停止 | 业务目标是否已验证、计划复核是否完成，或用户停止/资源边界/实际阻碍的依据 |

轮次目标用于确保持续执行，不伪造质量分数。一次回答列出多个方案不算多次独立调用，一次成功不代表稳定复现，重复模型意见不算新增目标事实。达到约定资源边界时报告全部已支持结论、覆盖限制和剩余候选；模型自评“信息增益低”不能替代资源约定或完成证据。

## 核查实际发送内容

发包前记录请求快照，区分需要保持不变的条件与刻意改变的条件。至少能定位请求行、头部和 Body 的实际变化；字符敏感时保留相关片段的 hex 或原始字节文件。

不要用字符数量代替字节长度，不要通过有损字符解码保存二进制请求。若依赖请求构造器，核查它是否重写了编码、头部顺序、长度、协议或 URL。

实际连接目标与 HTTP Host 分别记录。二者可以是有意的实验变量，但恢复历史或切换目标时不得遗失其区别。

改变压缩或格式时，核查转换前后的实体内容和业务字段。只改声明的实验明确标注；解析失败不能证明原语义越过检查。

## 比较响应前先验证可比较性

保存原始响应以及用于业务比较的解析结果，分清响应完整性、传输边界、内容解压和字符解码情况。HEAD、临时响应、分块或压缩响应应由可靠解析逻辑处理；不能默认把第一个头块后的所有字节视为完整业务正文。

超时、截断、读取上限、解析失败、未知字符集、无响应分别记录。获得少量字节与获得完整业务响应不是同一件事；内容无法可靠解码时仍可比较状态和原始字节，但不计算具有误导性的正文相似度。

区分发送前失败、部分发送和已发送但缺少完整回包；超时或连接关闭不能证明服务端没有执行请求。对可能改变状态的动作，重试前核对可观测状态与实际可重复性，方法名本身不能替代业务语义证据；无法确认时保留“处理结果未知”，继续不依赖该重试的研究。故障重试不与计划复验混计，重复发送后响应不同也不自动否定动作的幂等性。依据 RFC 9110 §9.2.2：`https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2`。

重定向保留每跳状态、Location、实际目标和后续请求条件。登录页面、公开首页或另一站点的 `200` 不能证明初始受限请求成功。按当前授权处理跳转；自动发送不要隐式越出范围或携带凭据到新来源。

发送方式不支持跳转时，保留原始 3xx 并报告该事实，不能把工具选项当作执行证据。

## 将筛选信号与确认结论分开

下表是常见观测示例。其他状态或无明显页面差异的情况，仍以所研究的业务边界和实际证据判断。

| 观测 | 当前可支持的判断 | 仍需要验证 |
| --- | --- | --- |
| 拒绝响应变为 200 | 响应或路由有变化，值得复核 | 身份、资源、业务内容、错误包装及缓存来源 |
| 405 / 415 或新解析错误 | 方法、媒体类型或处理入口可能发生变化 | 原语义是否被业务接受，是否触及所研究边界 |
| 3xx | 出现重定向流程 | 每跳的资源和身份，最终响应是否仍回答原问题 |
| 206 / 304 | 出现范围或缓存相关响应 | 内容来源、条件请求与实际可访问性 |
| 长度/相似度/标题变化 | 有辅助差异信号 | 动态字段、截断、格式、路由和业务内容 |
| 耗时或连接异常 | 有时间或传输差异 | 重复稳定性、负载、超时以及与假设的因果关系 |
| 本地解析预览还原成功 | 在该模型下关系成立 | 目标是否执行相同操作、入口、顺序与范围 |
| 同一受限身份稳定获取应拒绝的受控资源 | 有访问控制边界失败的业务证据 | 适用范围、必要条件与最小复现 |

相似度阈值用于挑选人工复核对象。依据基线波动和内容类型选择方法；项目的阈值、截断长度和正则归一化都只是工具实现参数。

归一化可能抹去关键的身份、资源标识、JSON 类型或字段值。保存原始响应，必要时比较稳定的业务字段和受控标记。即使相似度很高，某个关键字段的变化也可能有意义；相似度很低也可能只是动态错误页。

明确区分：候选差异、已有机制证据、检测边界失败、访问控制失败和独立业务影响。机制尚未定位但业务边界失败已可靠复现时，可以报告已确认行为，并把根因标为待定位。

## 用缩减和反证提高可信度

先判断实验是否有效：请求是否到达相关位置，必要触发是否存在，会话和资源状态是否可比，响应或日志是否足以回答问题。已验证的输入在可比条件下未命中，可以削弱相应解释；触发缺失、条件漂移或观测失败则保留未判定。只有矛盾证据覆盖了候选声称的条件，才据此排除。

候选复核后，保留原请求并逐项移除不必要的变换、噪音和组合条件。复核关键条件的必要性，以及简化后是否仍保持同一业务结果。

缩减时维持机制不变量：例如只在字符截断确有依据时保持低位关系；依赖数字解析时保持数字属性。变更输入如果破坏了前提，其失败不能反证另一个模型。

对仍成立的最小复现，记录至少一个能够区分主要替代解释的对照；若目标证据已直接排除替代解释，就引用该证据。不要把复发次数硬编码为所有目标通用的可靠性门槛。

复发失败时检查会话、一次性字段、缓存、并发、状态变化和发送条件。必要时把候选与基线交错执行，以识别随时间或状态发生的变化；执行顺序、具体字节及每次结果都保留。仍不能解释时降级为未稳定复现，避免用更多随机变体掩盖问题。

重复验证保留可比条件下命中与未命中的全部尝试，并说明条件变化。例如只命中一次时报告“同一条件下 10 次有效尝试中观察到 1 次”，把连接失败或条件失效的尝试另列；该比例只描述这些观测，不能直接当作模型置信度或后续请求稳定成功的保证。模型候选次数与目标验证次数分别统计，避免挑选成功截图后丢失探索过程。

## 记录与任务控制

证据记录按需要保留以下字段，不要求每个任务生成独立模板文件：

```text
目标：预期策略、受限身份、受控资源/动作、测试范围。
条件：连接目标与 Host、协议/TLS、会话、发送器、跳转/重试策略。
基线：请求/响应及保存位置、时间、稳定性或已知波动。
实验：假设、实际变更、前提、预测、对照、所属轮次。
观测：实际发送字节、响应完整性、逐跳结果、业务或日志证据。
结论：当前确认层次、已排除解释、剩余未知、最小复现。
限制：已花费请求数、未执行项、失败原因、停止原因。
```

批量实验先确定总量或上限，使用适合目标的并发和超时，计入基线、对照、重试与跳转。记录完成、过滤、失败和取消，展示过滤与证据保存分开；不能静默丢弃不符合默认筛选条件的结果。

取消等待不等于底层网络请求已经终止。停止后避免继续派发，晚到结果保持原轮次归属；清空展示不能让旧结果混进新实验。故障重试与计划复验分别记录：复验本身就是重复观察的目的，不需要新增报错或新机制才继续；两者都遵守资源和动作可重复性条件。

当前任务目标已有实际证据并完成对应复核后，可以完成结论与复现。用户要求停止、约定资源耗尽、执行能力实际受阻或服务出现实际异常时，记录停止原因与尚未完成的方向；不能因暂时没有新思路、少数失败或模型预测成功率低而提前结束，也不能把停止解释为“已经证明没有漏洞”。
