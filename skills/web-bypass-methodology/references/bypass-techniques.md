# 绕过技巧库：线索、实验与验证

用途：根据现场持续执行 WAF、401/403、访问控制或入口差异候选。它是可扩展的技巧库，不是保证有效的 payload 字典，也没有覆盖完成的固定顺序。多轮覆盖适用方向、表示、组合与复发，不能因模型认为某类成功率低或尝试几项未命中就提前终止。

表内请求、字符与字段均是受控示例。原请求有真实业务语义时，优先在已有位置变换；涉及新业务动作、目标地址或协议边界的方向，需要相应任务目标与范围。单次变化先作对照，必要组合再作拆解。

表中的支持条件和线索用于形成、解释与验证候选；未确认支持不等于已确认不支持。前提未知时仍可在当前范围内作受控实验，保存实际解析和业务反馈，再决定后续表示、组合或复验。单项与有机制依据的组合都可以进入队列，不以单项先命中作为组合前提。

对每个实例继续追问其底层操作：它改变检查对象、后续表示、范围、parser 分支、信任来源还是状态？沿该关系反推其他输入、位置与组合，不以同类 payload 数量代替机制探索。具体推导方法见 [第一性原理与机制推导](mechanisms.md)。

## 入口、域名与 IP

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| 已知源站直连 | 原域名 URL 用连接映射指向已授权源站，保留 Host/SNI | 同资源、同身份、同语义；源站来源限制或 mTLS 可能拒绝 |
| 域名/IP 表示差异 | 域名基线、正确名称的 IP 映射、IP 默认站点分别对照 | 只进入默认站点或证书不匹配不算原边界失败 |
| 已知别名、备用入口、端口 | 复用流量/部署中已有入口并核对同业务 | 关联资产不等于授权；公开接口不等于受限接口 |
| IPv4/IPv6 与协议入口 | 对同域名已知地址族、HTTP/HTTPS 或支持的协议作比较 | 记录连接地址、协商协议及入口保护差异 |
| 域名格式与 authority | 有依据地对照大小写、尾点、端口或 IDNA 表示 | 名称归一化、证书和后端路由都需检查 |

连接变量、对照设计及 Host/SNI 条件见 [连接与入口](connection-routing.md)。

## 路径与资源规范化

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| 尾斜杠与相邻斜杠 | 已有 `/restricted/report` 对照尾部 `/`、局部 `//` | 客户端要保留 target；确认最终仍同资源 |
| 点段与局部路径表示 | 对照局部 `/./`、受控等价点段，不引入真实敏感文件 | 客户端或入口可能提前规范化；等价性由目标确认 |
| percent 编码与多阶段 decode | 在已有路径段/分隔位置比较 `%2e`、`%2f`、`%5c` 或相应双层表示 | 有第二次解码才支持多层解释；被拒绝或走另一资源时不成立 |
| 分号、矩阵参数与路径边界 | 已有段尾增加受控 `;probe=1`，比较该段及边界位置 | 验证矩阵参数、鉴权对象与最终路由是否分别处理，确认同资源 |
| 扩展名/后缀与内容协商 | 比较已支持的 `.json`、尾部静态形态、Accept 或已有扩展入口 | 可能触发另一路由、下载页或静态页；需要业务等价证据 |
| 大小写、斜杠/反斜杠 | 局部改变既有段或分隔符 | 与平台、文件系统、容器及代理配置有关 |
| 空白、控制字符或 NUL 候选 | 有明确解析线索时，局部检查已编码字符的接受/规范化 | 现代实现通常可能拒绝，不能作为默认通用能力 |
| 清洗顺序与非标准路径 | 从已有受测 token 比较 `....//`、双层分隔符、旧式 `%u` 或过长字节表示 | 区分一次清洗、反复清洗和后续 decode；非标准输入需入口/版本证据，不能默认等价 |
| 已发现的路径别名/版本/handler | 从 JS、流量或文档中选择同资源的实际入口 | 要确认授权策略是否应一致；不以目录猜测取代端点发现 |
| rewrite 与内部转发差异 | 对有线索的重写入口比较原始 target 和最终业务资源 | 日志、业务标记或稳定字段帮助确认；无需先猜定代理产品 |

规范化、代理 location 与应用授权可能使用不同对象；参考 [T1–T2]，目标配置与版本仍需验证。

## 噪音、分隔与插入位置

项目的噪音区包含 `%00`、`%09`、`%0a`、`%0d`、`%20`、`%0b`、`%0c`、`%a0`、`%2b`、`/**/` 及 Dirty/Null 数量占位。把这些分为 encoded 控制字节、空白候选、语法注释和长度/解析边界方向，分别判断最终语义。

同一原子可在选区、路径末尾、单段前后、目录边界、字符间或已有空白位置使用；单个位置和作用范围变化分别记录，避免把一个位置的失败代表整个方向。插入注释依赖对应语法，`%a0` 依赖字符集，`+` 的空格解释依赖 form 解码。Dirty/Null 要核查展开后的真实字节、数量和标记位置，不把占位文本或响应变化当作实际边界证据。

已有长度/检查范围线索时，可以在约定资源内持续覆盖相应位置与长度条件；总尝试轮次、单请求体积和并发分别管理。技术说明与编码区别见 [编码与解析器技术](encoding-and-parsers.md)。

## 方法与方法覆盖

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| GET / HEAD / OPTIONS | 在受控、可重复资源上比较状态、Allow 和处理入口 | HEAD 无正文不表示拒绝，OPTIONS 单独放行不代表资源读取 |
| 业务确实支持的其他方法 | 根据已知 API 操作对比可控方法 | POST/PUT/PATCH/DELETE 可能产生状态变化；不盲发 |
| `X-HTTP-Method-Override` 等 | 用受控请求检验覆盖字段是否参与解析，并比较鉴权与最终方法 | 支持方式由目标决定；未知时保留验证，确有反证时记录条件范围 |
| form/query `_method` | 在受控、允许的动作上比较实际方法、参数位置与取值 | 字段可能只是普通业务参数；method 与 Body 必须可比 |
| 方法大小写或非标准方法 | 明确怀疑默认 handler/鉴权枚举不完整时作受控探针 | 400/405 或静态应答不表示业务动作被允许 |

参考 HTTP 方法与覆盖测试 [T3]。方法变化后的动作是否等价需要独立验证。

## 头部、代理信任与 URL 覆盖

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| 转发来源 IP | 一次选择 `X-Forwarded-For`、`X-Real-IP` 或 `Forwarded`，用受控来源标记比较 | 验证入口覆盖与业务信任来源；字段内容不改变真实 TCP 来源 |
| 代理链首项/末项/多值 | 用受控两项链比较 first/last 或实际位置选择 | 需要头部确实被采信的证据，重复/无效值可能直接被拒绝 |
| 历史客户端 IP 头 | 以单项及有依据的组合检查 `X-Client-IP`、`X-Originating-IP`、`X-Remote-Addr`、项目自定义 IP 头 | 记录组合，复核采信来源及必要字段，避免把忽略头部当有效信任变化 |
| CDN 专用来源头 | 有线索时检查项目手动区的 `CF-Connecting-IP` 等实际入口字段 | 需验证客户端输入是否被覆盖及哪些代理受信任，头名本身不能证明来源 |
| `X-Original-URL` / `X-Rewrite-URL` | 用不存在受控路径判别改写，也可直接对照入口允许路径与实际受限 target；支持情况由回包更新 | 同一受限身份获得受限业务结果才支持边界失败；无需先证明支持才保留候选 |
| Host/Proto 转发头 | 单独对照 `X-Forwarded-Host`、`X-Forwarded-Proto`、实际 `Forwarded` 字段 | 可能只改变链接生成、跳转或虚拟主机；需要实际策略证据 |
| Origin / Referer / 客户端条件 | 比较已有正常调用与候选请求，补齐或局部改变有依据的字段 | 恢复合法调用条件通常属于正常访问；区分 CSRF、会话与 WAF |
| User-Agent / Accept / 请求标记 | 对照目标已有客户端的实际字段 | 可能是客户端门槛或内容协商；不能代表真实身份改变 |
| Cookie/头部重名与顺序 | 用当前允许的测试会话和受控重名字段观察解析优先级 | 保存实际字节与最终身份；不误用其他账户会话作为成功 |

URL 覆盖与来源字段取值参考 [T2、T4]。产品支持某个字段，不意味着当前部署允许客户端控制该字段。

## 参数位置、重复与结构

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| Query / form / JSON 位置 | 按业务实际支持的入口移动已有值，保留其他字段 | 参数来源优先级和业务语义必须验证 |
| 重复参数 HPP | 先以 `probe=A&probe=B` 判断 first/last/list/拼接，再对已有受测值变换 | WAF 与后端取值差异才有意义，需保存顺序与最终值 |
| 参数名编码/大小写 | 在已知字段名上比较局部 percent/JSON escape 或大小写 | 解析器可能不认该字段；缺字段错误不算保留语义 |
| JSON 重名键、数组与标量 | 用受控标记确认实际取值或类型转换 | 可能改变语义、拒绝格式或走不同校验；不能默认等价 |
| 分隔符与参数解码顺序 | 在现有受测参数上比较编码分隔符、不同位置和必要嵌套 | 分割前/后解码、重复解码都需实际证据，不能只靠本地库 |
| 参数片段在后端组合 | 业务确实组合字段时，观察受控片段最终结果 | 拼接机制是前提；不凭字段拆开就假定攻击语义恢复 |
| 不同承载位置的覆盖差异 | 已知业务读取头部、Cookie、路径字段等时比较同值 | 字段未被业务使用就是无效变体 |

为候选指定要保持的受控最终值，并随请求核对实际消费结果；未知取值规则可以通过单项或组合对照验证。参考 HTTP 参数污染 [T5]。

## Body、媒体类型、压缩与上传结构

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| 真实 format 转换 | 将 form/JSON/multipart 的已有受控字段真实转换，以请求验证接收支持 | 类型、重复值、嵌套、文件字节与字段语义保持可比 |
| 仅改变 Content-Type | 保持实体字节，局部改变声明或可接受媒体类型 | 声明与实体不一致明确记录；415 只是一条解析线索 |
| charset 与参数解释 | 分别尝试 UTF-16/BE/LE、UTF-32/BE/LE、IBM037、手动区 cp290，以及 charset 首尾位置 | 前提未知时保留探索；核对真实编码、BOM、可逆性和声明，不能把一项失败外推到其他编码 |
| Gzip / 内容编码 | 对原实体真实编码并验证接收，保留解码前后证据 | 后端确实解压且检查层行为有差异；避免无意重复压缩 |
| multipart boundary / part 字段 | 局部改变受控 boundary、引号、part 类型或重复字段 | 需要两层解析结果和原业务字段；保持 framing 一致 |
| `filename` / `filename*` / 编码名 | 在可回收的无害测试文件上比较解析与保存名称 | 实际解析版本、字符集和保存名决定结果；不上传执行型文件来替代名称验证 |
| JSON/XML 等解析宽严差异 | 有支持线索时用局部转义、合法空白或受控非标准结构判别 | 接受一类语法依赖实现；格式失败不代表检测语义保留 |

普通变换同步实体字节长度与相应声明。压缩、分块或二进制输入先识别再重建；具体原子见 [机制推导](mechanisms.md)。

## 编码、字符与多阶段解析

本节是候选索引；实际展开时读取 [编码与解析器技术](encoding-and-parsers.md)，其中逐项区分项目的 URL/Path、强制全字节、混合/双层、字符集、字符变形和 11 个 parser/场景方向，附局部实现依据。不能把表中的一行当成该技术族已经覆盖。

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| URL 单次、混合与双层编码 | 在已有 token 的相关字节上局部编码，比较实际 decode 结果 | 安全字符可能无变化；编码深度按真实链路决定 |
| JSON Unicode / slash escape | 在原字符串或字段名中比较合法转义表示 | JSON 解码后值和字段应恢复；不能把非法 JSON 当等价 |
| HTML entity / JS escape | 对已有输出上下文内受测片段作局部语义对照 | 只有目标上下文确实解码才成立；JSON/HTML/JS 阶段不能混用 |
| Base64 / 其他实际解码 | 在已有受测值上比较表示，并用受控标记验证业务是否解码 | 未知解码能力保留候选；未恢复原语义时不能认定绕过 |
| Unicode normalization / 同形/全角/零宽 | 对受控值比较真实归一化与安全判定位置 | 视觉相似不代表字符等价，字段改变可能导致业务失败 |
| 低 8 位 / 低 7 位 Ghost 候选 | 用目标操作所需不变量生成字符，再验证到达该调用入口 | 必须区分字符缩窄和 UTF-8 编码；预览不证明真实目标 |
| Unicode 数字 / 宽松 hex | 针对已有 percent 或 escape 结构验证实际 parser | 数字属性不能任意换组；依赖版本、入口和处理范围 |
| 多阶段转换与触发分支 | 先设计受控最终语义与必要中间态，再验证有/无触发及其位置 | 每个转换箭头都要依据；不能默认全路径或全部字段一起转换 |
| 历史非标准编码 | 在范围内比较 `%u`、非法 hex、旧式字节接受等，记录已知或未知的版本与入口 | 非标准输入可能直接被拒绝；未知版本不自动淘汰候选，不能预设合法或等价 |

项目的 Ghost Bits 与 parser 能力提供操作模型，来源与局限见 [项目说明](project-lineage.md)。

## 检测范围、回退与协议入口

| 技巧方向 | 候选实验 | 验证与失效条件 |
| --- | --- | --- |
| 规则检查字段遗漏 | 用业务确实消费的字段，比较头部、Cookie、query、body 的检查覆盖 | 规则与业务消费位置均需证据 |
| 解析失败/格式回退 | 在明确 JSON 等处理线索时，局部观察失败后拒绝、字符串检查或回退 | 回退可能仍拦截，也可能只改变错误；查目标配置 |
| 长度/检查边界 | 请求成本可控时，围绕已知或待验证的边界展开相邻条件、位置、组合与复验 | 限制随服务和配置变化；总轮次、单请求体积和并发分别管理，不能用固定阈值套全部 WAF |
| 规则前处理与 decode 顺序 | 比较合法等价表示、组合顺序及位置 | WAF 可能已做相同还原，不能假定编码自动逃过检测 |
| HTTP/1.0 / HTTP/1.1 / HTTP/2 路径 | 工具和目标支持时维持语义，记录实际 wire 与协议 | 代理转换或默认站点可能改变处理；不是天然绕过 |
| header 大小写、排列或重复解析 | 有线索时以非 framing 的受控字段作局部对照 | 头部可能被库重写，或目标直接拒绝不规范输入 |
| CL/TE、HTTP/2 降级与请求边界差异 | 作为独立协议研究方向，先查配置、日志或隔离环境复现 | 不纳入普通自动变体；只有任务明确允许且有隔离条件才做可能影响其他请求的实验 |
| Bot/challenge、频率或客户端门槛 | 比较合法客户端会话、正常速率与原请求的具体条件 | 与内容 WAF、认证边界分开；不默认轮换未知出口或批量规避挑战 |

检查范围、JSON 回退与前处理参考 [T6–T8]；协议边界是单独的实验，不使用大体积、压缩膨胀或高并发来代替可判别测试。

## 与原测试语义结合的技巧

如果任务已经有受控 SQLi、XSS、命令解析、路径访问或 URL 校验样本，模型可从相应语法继续推导：SQL 方言的合法空白/注释/关键字与等价表达式，HTML/JS 的实际解析上下文，shell 的真实引号/转义语义，路径规范化顺序，URL parser 的 authority/编码解释。先用无害标记或已有测试样本证明语义恢复，再解释 WAF 差异 [T9–T10]。

这些类别不是自动引入的新攻击目标。没有用户给定或任务内建立的语义时，先研究已有请求和可控标记；不生成下载执行、持久化、敏感文件读取或外部回连链来充当“绕过确认”。

## 扩展技巧而不固化思路

技巧来源包括模型已有知识、现场现象、原项目、目标源码和官方文档。各轮持续验证方向、展开表示与组合、变换观察角度并复发已有候选。遇到本库未涵盖的机制直接研究，不把目录当成封闭清单；一次遍历、模型共识或连续未命中均不证明已经覆盖充分。

厂商、组件版本、CVE 名称和“网上有人成功”的记录只用于定位具体前提。需要精确版本行为时查对应实现；不能把相关组件名直接转成漏洞结论，也不能为了补齐所谓“全部技巧”机械发包。
