# Web 绕过研究方法论

执行授权范围内的 Web 绕过研究，直到当前目标取得可复核结果，或遇到明确的停止依据。自主获取现场、维护候选、发送请求、读取回包、展开下一轮并复验；BypassPro 提供技术经验，工具按实际环境选择。技能包只沉淀方法论与参考资料，不附带脚本或固定命令配方。

衡量工作质量的是结论的可靠性、解释力和复现成本。变体数量、工具数量与命中状态码不能替代这些目标。

默认增加候选生成轮次、实际尝试覆盖和复发次数。模型输出，包括“不可能”“已排除”“足够了”等判断，都先作为待验证论断；模型认为自己已经想全，不能代替充分探索。每轮尝试和每次回包持续更新研究状态。

## 执行要求

- **把分析落实为行动**：任务已允许测试且工具可用时，持续构造、发送、读取与复核。准备好了下一项范围内的动作就执行；阶段汇报之后继续工作，不把技巧建议或待办清单当成任务完成。
- **从底层关系生成技术**：把目标边界拆成实际身份、对象、表示、转换、检查范围、使用位置和状态，反推失配可能产生在哪里。技术名和项目模板用于举例；没有现成名字的候选也进入探索。
- **未知前提进入验证**：目标产品、版本、解析入口、支持格式与转换顺序可以未知。参考资料中的“需要支持”“有线索”等用于解释结果，不意味着必须先证明全部前提才能尝试；用受控候选获取这些证据。
- **保留探索广度**：从现场形成可扩展的方向集合，持续覆盖不同机制、位置、表示和必要组合。模型低置信、某类不熟悉或少量失败不能成为永久淘汰依据。
- **把抽卡落实为轮次**：重新生成、改变已有候选、真实执行和重复复验分别推进。一次长答案中的多个方案不算多次模型调用，多次模型一致不算新增目标事实。
- **让回包改变安排**：保存每次动作及结果，更新候选状态、剩余覆盖与下一轮任务。命中、未命中和未判定都保留；发现变化后继续复验，连续不变时继续展开或重试既有候选。
- **处理执行故障**：单次超时、工具报错或一次不完整响应先定位原因，并用已有能力修正或替换发送方式。没有发到目标不记作技术失败；已发送而缺少回包时，服务端处理结果仍可能未知，涉及状态变化的重试先核对实际状态与动作可重复性。确认无可用执行路径时才报告能力阻碍。

这些是工作约束，不是固定阶段。信息获取、广度探索、组合尝试、重复验证和缩减可相互穿插；简单性用于减少无关假设和副作用，不能代替用户要求的轮次与必要覆盖。

## 从真正的边界问题出发

先用已有材料明确当前问题，缺失项按是否影响下一步来处理：

- **预期边界**：哪个身份，对哪个资源或动作，按什么策略应当被允许或拒绝？WAF 场景中，当前要证明的是检测失效、请求到达业务层，还是进一步的业务安全影响？
- **已知现场**：原始请求和响应、实际网络目标、会话状态、拦截现象、已有正常请求、可用源码或日志。标明哪些是直接观测，哪些是推测。
- **执行约束**：沿用当前会话已明确的授权范围、测试账户、允许动作和请求预算。授权不明确时先做离线分析，只询问影响实际发送的缺口；技能调用不增加外部操作权限。
- **成功证据**：提前选择能验证目标的业务字段、受控资源标记、处理日志或其他可靠观测。单纯“与原响应不同”只是发现线索。

现成材料已经回答的问题直接采用。只有一个响应样本时持续核对基线稳定性；有源码时可直接定位关键操作；已有可靠复现时可穿插解释与缩减，不取消尚未完成的研究范围。新观测与已采纳事实冲突时，核查材料来源、时间和执行条件，修正有误判断并保留依据。

## 主动获取现场并推进测试

当前任务已允许对目标测试且有可用工具时，持续执行适用候选、对照与复发，不能只交付“建议试试”的技巧清单，也不能做完少数请求就自行宣布探索结束。只提供离线材料或没有可用连接能力时，继续完成材料提取与多轮候选推导，明确尚未实际执行的部分。

从现有请求与返回包中提取：连接目标、协议、状态、认证挑战、跳转、媒体类型、Cookie 名称与属性、代理/缓存/追踪头、错误模板、稳定业务字段及耗时。把这些当作线索组合，不能凭一个 `Server` 头断言后端栈，也不能把所有 403 判为 WAF。

现场信息获取与候选执行并行推进。从原请求、已有正常请求、受控不存在路径、同结构不同值、合适的方法和各类表示差异中持续展开对照与尝试。首轮结果用于启动下一轮，不把首轮安排当作总额度。记录各轮覆盖、候选复发及反馈，不把单次样本代表整个方向。

各轮回包持续更新拦截层假设：DNS/连接/TLS、CDN/反向代理/WAF、Web 服务器/路由、认证鉴权、业务输入校验、缓存或客户端会话。继续选择并执行适用技巧、表示与组合，同时反复复核关键候选；拒绝模板不变只是一组观测，不能仅凭它结束方向。出现新业务信号后保存证据、增加复发与对照，再缩减。

维护可继续执行的研究状态：原始证据、当前假设、候选及条件、已测/未测范围、生成轮次、实际发送与复验次数、剩余工作及资源。记录服务于下一项行动，不要求为简单请求填写长报告。

根据问题读取以下资料；技术栈未知时从底层关系和已有请求形成候选，可借技巧索引补充实例，不等待猜定产品后才考虑技术。详细资料按需展开，不把目录当成固定扫描顺序：

| 当前问题 | 读取材料与动作 |
| --- | --- |
| 需要深入底层、推导新技术，或现有思路趋同 | [第一性原理与机制推导](references/mechanisms.md)，研究不同表示、转换顺序、类型/范围、回退、信任及状态的检查与使用关系 |
| 只看到错误码，服务端与拦截位置不清 | [回包分析与持续探索](references/reconnaissance.md)，提取事实并反复尝试与比较 |
| 域名被拦、IP 可达、怀疑源站或虚拟主机差异 | [连接、域名与入口](references/connection-routing.md)，分别控制连接地址、SNI 与 Host |
| 已有 401/403 或 WAF 线索，需要可执行候选 | [绕过技巧库](references/bypass-techniques.md)，按前提挑选路径、方法、头部、参数、Body 或解析差异 |
| 需要展开编码、字符集、Unicode、Ghost 或具体 parser 技术 | [编码与解析器技术](references/encoding-and-parsers.md)，区分各类原子、位置、还原条件并多轮展开变体与组合 |
| 需要组织实际执行、重复验证、未命中或未判定结果 | [实验与证据](references/experiments.md)，维护候选状态、对照、复发与缩减 |

技巧库提供底层关系的实例。候选也可以直接来自现场、源码操作和第一性原理；使用模型已有知识与对应官方资料扩展库中未覆盖的方法。把新技巧写成“操作/决策关系、未知前提、实验、预期还原/业务结果、反例”；不把技术名、历史成功或模型推理当作目标事实。

## 将技术展开为下一轮候选

从当前请求和业务目标形成候选队列，区分待执行、已执行待判定、条件内未复现、有业务信号待复验、已确认及有证据排除的条件范围。未知前提留在候选中；失败记录保留原条件，不自动禁止其他表示、组合或再次复验。

以下方向用来辅助检查遗漏。生成新候选时同时研究其底层操作和检查/使用关系，允许跨类别或引入新类别；按现场增删和调整顺序，不要求固定笛卡尔积，也不把未知类别自动标为“不适用”：

| 可展开的方向 | 在候选中明确什么 |
| --- | --- |
| 入口与路由 | 连接地址、端口、URL 名称、SNI、Host/authority、协议、同业务判据 |
| 身份与信任 | 真实身份、资源归属、来源元数据、URL/方法覆盖，实际决策对象 |
| 路径与边界 | 后缀、段前后、目录边界、点段、分隔符、矩阵参数与最终资源 |
| 方法与参数 | 最终方法、参数来源、重复/顺序/结构、字段名和值的实际消费 |
| 字节编码 | URL/Path、强制全字节、混合/多层、Unicode/上下文转义、Base64 |
| 正文与声明 | UTF-16/32 的端序/BOM、EBCDIC、charset 解释、真实格式转换与声明伪装、gzip |
| 字符与 parser | 全角/同形/零宽/大小写、低 8/7 位、Unicode 数字、hex/escape 宽严与实际入口 |
| 检查范围与组合 | 承载位置、噪音/长度条件、解析回退、转换顺序及必要触发 |
| 执行与状态 | 实际字节、客户端改写、会话、缓存、时间条件和复验稳定性 |

每个待发送候选能说明：要检验的边界、原请求的变更位置、需要保持的身份/资源/语义、未知前提、预期业务观测，以及对应的基线或反向对照。简单候选可简记，关键组合保留中间表示。没有根因解释也能继续收集证据，不编造未观测的后端步骤。

每次结果回写后继续推进：未发送先修复执行；无变化保留该条件下的负结果并展开/复发；新解析错误用来研究接收与转换条件；路由或业务变化先排除身份、默认站点、跳转和缓存解释，再复验或缩减。响应可以支持其他解释，状态码不能机械决定分支。

## 建立可修正的链路模型

先写清应保持的边界关系，再对相关节点观察：输入类型与来源、实际操作、作用范围、成功/错误分支、输出及使用它的身份/资源/状态。缺失节点留为未知，链路可以含缓存、转发和状态分支；不要求先解释完整后端才能发请求。

按实际证据画出相关部分，例如：

```text
编辑器/请求构造器 → 实际发送字节 → 入口代理/安全检查
               → 路由与身份处理 → 解码/业务解析 → 资源或动作
```

这只是画法示例。实际链路可能更短、顺序不同，或者没有 WAF；未知节点保留未知，不用产品名填补证据空白。

对可能影响结论的节点，关注它收到什么表示、执行什么操作、输出什么表示、用什么对象作安全决策。字节、Unicode 字符、解析后的字段、规范化路径与实际资源必须分清。

同时保留两个问题：**是否存在表示或处理差异？是否存在策略或信任关系错误？** 正常解析出完全相同的请求，也可能因身份、资源归属或信任来源错误而越权。反过来，解析差异也可能只产生无害的错误页。

从相关操作继续发散：反推同一受控业务结果的不同输入表示；寻找检查层认为相同而业务层不同的输入；比较解码、拆分、归一化与检查的次序；核对字符/字节、位宽、类型、长度单位及局部检查；追踪错误回退、名称解析、来源信任和检查后状态变化。这些是推导角度，不是封闭目录。具体模型与可判别实验见 [第一性原理与机制推导](references/mechanisms.md)。

只补全会影响实验或结论的未知信息，用已有流量、源码、配置和日志逐步验证。局部模型下等价、不相等或顺序差异都是线索；最终仍以目标契约、受限语义和业务证据判断边界。

## 让假设接受反证

为值得测试的解释交代清楚：

```text
观测：实际看到的现象。
假设：哪一层的哪种决策/转换可能产生该现象。
前提：已验证条件，以及尚未验证的条件。
实验：最小有意义的变更，保留哪些身份、资源与语义。
预测：假设成立时应出现什么；替代解释会出现什么。
反证：什么结果会否定或削弱假设。
```

这是思考工具，不要求每个简单操作都输出整套表格。存在明显替代解释时，选择能区分它们的对照；不为凑数量臆造假设。优先选择能改变判断、成本适当且容易观察的实验。比较解释时，先看它们能否覆盖关键观测并满足目标，再优先选择额外假设、机制和副作用更少的方案；必要的复杂度由证据决定。

证据不支持当前解释时回到模型，检查身份变化、路由变化、客户端改写、缓存、动态响应或前提不成立。不要把“没命中”自动解释为编码不够复杂。

## 持续多轮推导与反复尝试

把模型每次输出按“抽卡”理解为一次候选生成，默认进行持续多轮推导、方向覆盖、实际执行与反复复核。首轮答案、几轮答案一致、模型低置信或暂时没有新想法，都不足以停止绕过研究。增加轮数的目的包括重新抽取被遗漏的方向、变换已有候选、重复观察目标以及检验先前结论。

每轮保持目标、硬约束和已验证事实，重新审视尚未验证的前提。尽量从原始材料重新提出候选，减少上一轮结论的锚定；也可选择另一种有依据的观察角度，或专门寻找当前首选解释的反例。轮次和切入角度随问题调整，不固定次数、角色或提示词套路。

比较多轮结果时，关注机制、成立条件、表示变化、组合、实际覆盖与复发结果。重复已有候选可以用于稳定性、状态依赖或先前漏测条件的验证，不要求每轮先产生新机制才允许继续。只重新写长答案不算实际尝试；候选合并保留不同输入、执行条件和验证记录。

多次一致不能提高事实等级。不同输出可能共享同一错误前提，少数候选也可能更有价值。按证据、可证伪性、假设数量、成本和与目标的关系排列执行顺序，允许保留分歧；排序不能代替用户要求的持续覆盖，最终用实际验证裁决。

重复模型推导与重复目标请求分别管理预算，记录计划轮次、实际轮次、候选覆盖、复发次数和剩余任务。离线检查核对目标、授权范围与候选的实际可构造性，不以模型主观成功概率作为发包门槛。有意研究的非标准语法、声明不一致或本地解析拒绝仍可作为候选，以目标证据判定；不能因违反标准或本地解析失败自动淘汰。低置信候选和未命中方向，只要仍有适用可能且在约定范围内，就保留后续验证机会。具体做法见[实验与证据中的重复方法](references/experiments.md#重复推导与重复验证)。

结果趋同或连续未命中时，重新从原始材料生成候选、改变观察角度、展开尚未覆盖的表示/组合，或对关键候选继续复发与对照。阶段总结用于启动下一轮，不自动结束工作。停止依据是当前目标已有足够证据完成、用户明确停止、约定资源耗尽、执行能力受阻或实际出现需要停止发送的异常；不能以模型自评“信息增益低”替代这些依据。达到资源边界时交付覆盖和限制，不能宣称不存在绕过。

## 从机制推导变体

技术覆盖应落实到独立机制，不能只写“试编码”就视为覆盖 URL/Path、混合/多层、字符转义、UTF 端序、EBCDIC、字符变形、低位缩窄或 parser 容错。按现场展开作用位置、表示、必要组合与复发，并保留尚未验证的条件。项目按钮、预设策略和自动变体数量用于追溯经验，不限制 agent 的技术范围、生成轮次或重复执行。

候选可以来自已有机制，也可以用于获取链路信息。前提未知时安排实际尝试并持续观察；只有实际证据在明确条件内否定前提，才在该范围内排除分支。模型推断其不成立或若干次未命中不等于可靠否定。发送前说明作用位置、相关条件及观察方式，把探索线索用于后续轮次。

原请求提供了业务语义时，先利用已有字段或结构；引入新资源、新动作或完整漏洞场景属于另一项测试，需要相应目标和授权依据。

单因素对照用于归因，不是候选生成的限制。可直接构造有机制依据的组合，即使单个因素尚未命中；声明、字符集、位置、转义、触发和后续 decode 可能需要共同成立。命中后通过移除条件、改变顺序、替换触发点或局部对照判断各部分作用；同时保留其他方向的持续执行。

需要展开时按当前问题读取：

- [第一性原理与机制推导](references/mechanisms.md)：节点契约、表示反推、转换次序、类型/范围、回退、名称与信任、状态及源码下探。用于生成新技术与实验，不是必扫目录。
- [实验与证据](references/experiments.md)：选择下一步、重复推导、建立对照、核查字节与响应、缩减复现和记录。用于实际测试、复核候选或研究停滞时。
- [项目来源与适用边界](references/project-lineage.md)：追溯提炼依据或继续维护技能时读取。无需安装或运行原项目。

工具按所需能力选择。Burp、脚本、代理、日志或本地最小程序都可以使用；选择 Raw 发送的依据是实验需要保留哪些字节，以及现有发送器是否会改写它们。

## 保护实验成立的条件

- 以实际发送字节为准。区分编辑器显示、选区文本、重建请求和线上字节；字节敏感实验保留可检查的字节证据。
- 对照维持需要保持的身份、会话、业务资源和业务语义。改变这些条件可以是实验本身，但必须明确记录，避免把换身份或换路由误认为原边界被绕过。
- 区分实体 Body 与压缩、分块或二进制表示。无法可靠解码和重建时保留其字节，跳过相关文本变换并说明原因。
- 在构造正常实体请求时，长度、编码声明和结构随实体字节一致变化；若研究的正是其中的不一致，单独定义实验，不让重建请求意外引入该变量。
- 比较请求行、头部和 Body 的内容，而非只看长度。相同请求可按复发计划反复执行，观察状态依赖、偶发差异和先前验证的可靠性；字节去重只用于合并候选描述，不自动取消复发。模型等价只说明该模型下的关系，目标是否采用该模型仍需验证。
- 每次发送保存目标、发送方式、请求、响应和所属轮次的快照。重定向、重试、恢复历史、取消后晚到结果，都不能悄悄改变实验归属。

## 判断结果与选择下一步

分别判断**观测到了什么、边界是否失败、机制解释到什么程度**。业务证据可以先确认边界失败，机制仍待定位；本地模型也可以先验证某种转换，目标边界仍未确认。报告每项结论的证据，避免相互替代或要求固定确认顺序。

状态码、相似度、长度、标题、耗时和解析错误帮助挑选候选。状态码保持不变或页面高度相似时，关键业务字段、资源或权限变化仍可能构成有效证据。确认访问控制失败需要同一受限身份确实访问了应拒绝的资源或动作；确认 WAF 检测失效需要请求保留相关语义并跨过预期检测边界。进一步的漏洞或业务影响需要独立证据。

负结果只覆盖实际测试条件。实验缺少必要触发、会话已失效或观测不可靠时，记录未完成判定，避免据此排除整个机制。缺少日志、响应不完整或预算耗尽时，记录限制和最有价值的后续验证，不写“目标不存在绕过”。

持续研究同时增加候选生成、适用方向覆盖和复发验证。预算计入基线、对照、重定向与重试，执行前能说明轮次目标和资源约定；总轮次与并发/发送速率分开管理。出现约定资源耗尽、明显服务异常或越出授权范围时停止相应发送，记录尚未完成的方向。

得到候选命中后，增加复发和必要对照，再缩减为最小证据并解释根因。保留可比条件下的全部有效尝试，包括未命中结果；偶发命中写清尝试数量、状态依赖和不确定性。一个方向成功是否完成整个任务，由用户目标决定，不能自动跳过尚需研究的方向。

## 交付能被复核的结论

按任务复杂度输出必要内容：边界目标、已验证事实、关键未知、候选与淘汰理由、最小请求/响应证据、实际目标和发送条件、复现方式、结论层次及限制。适用时说明应修复的信任、授权或解析一致性问题。

不要求统一报告模板。离线分析写清尚未发包，网络失败写清尚未判定，推断写清依据。敏感证据保存在当前允许位置，分享时移除凭据和业务敏感数据。

多轮或跨上下文工作保留简短研究状态：证据位置、当前候选、已排除的条件范围、剩余分歧、已用预算和下一项判别实验。新一轮复用这些事实与记录，同时重新审视推断；只在当前任务确有需要时保存文件。

维护本技能时，把新经验加入为“机制、成立条件、判别实验、反例与证据范围”。允许提出参考文件未覆盖的机制，允许删除已被证伪的判断；具体框架、字符、路径、状态码、顺序和历史命中次数都不能成为通用前提。没有实际行为评估时，只报告文档与结构改进，不把校验通过声称为绕过能力已被证明。
