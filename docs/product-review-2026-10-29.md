# BypassPro 功能与操作体验评审

日期：2026-10-29。对象：当前工作区，包括本次配置保存与英文界面修改。

## 结论与依据

优先让用户能够确认作用范围、实际修改、发送目标、任务状态和结果依据，再扩展扫描能力。当前功能数量已经足够支撑完整测试流程，但这些环节的信息和行为存在不一致。

本次检查包括源码审查、实际 Swing 面板的离屏渲染，以及使用临时配置和 Burp API 替身进行操作复现。没有连接真实目标，也没有在实际 Burp 的 Pretty/Raw/Hex 编辑器里完成端到端验收；编辑器选区、焦点、高 DPI 布局仍需要实际 Burp 验证。

英文界面修改已完成，Java 8 全量 72 个测试通过。下列内容保留评审时的缺陷与复现证据；当前修复状态见下表。原有测试之外已补充操作链路回归测试。

## 第一批：修复影响正确性的行为

### 1. WAF 选项保存报告成功，但部分开关没有保存

**已复现。** 使用默认配置，把 `utf_16`、`gzip`、`multipart` 改为 `false` 后调用 `saveWafOptions`，返回 `true`，重新读取却仍为 `true/true/true`。

原因：`ConfigLoader.patchWafOptionsSection` 向 `patchNestedBools` 传入子字段缩进 6，后者在缩进 4 查找父节点；实际父节点为 6、开关为 8，未找到节点就直接返回，最终仍显示保存成功。

源码：`src/main/java/Main/ConfigLoader.java:287`、`:421`。

建议：先修正缩进参数；保存前后按用户提交字段核对结果，不能只把文件写入成功作为业务保存成功。补默认完整配置的开关保存、重新加载测试。

验收：取消勾选 → 保存 → Reload → 重启插件后，该开关仍关闭；生成的请求与开关一致。

### 2. 历史重放没有恢复发送目标

**已复现。** 历史包含 A 站点请求，当前载入 B 站点；加载 A 的历史后，请求头恢复为 `Host: a.test`，顶部发送目标仍为 `b.test`。

原因：`loadHistoryRequest` 只恢复请求字节；发送过程使用独立的 Host / Port / HTTPS 字段。History 的 Raw 记录也没有完整目标信息。

源码：`src/main/java/Main/ManualWafPanel.java:1529`、`:3863`。

建议：历史记录保存并恢复请求、响应、目标主机、端口、协议和发送模式。把“网络目标”和“HTTP Host”分别显示，允许有意构造不一致的请求，但不能因恢复遗漏而悄悄不一致。

验收：A → B → 加载 A 历史 → 请求、网络目标、发送模式均恢复为 A 的快照；手动修改 Host 头不自动篡改网络目标。

### 3. 候选判定与最终入表过滤不一致

**源码确认。** `isCandidateStatus` 接受 206、304、多种 3xx、200、405、415，但 `addLog` 最终仅保留 200、405、415。前一步判定有差异的结果可能被后一步静默丢弃。

源码：`src/main/java/Main/BypassMain.java:336`、`:692`。

建议：统一结果判定；记录与显示过滤分开。默认展示有信号结果，并可切换全部结果、错误、已过滤结果。405/415 应标注为解析或方法差异线索，不能仅凭状态码标为绕过成功。

验收：403 → 302、403 → 206 等结果有明确记录或过滤原因；用户可以追溯，不会无声消失。

### 4. 完成、失败、清空没有统一任务状态

**进度问题已复现。** 计划 1 个请求、失败 1 个，错误数显示 1，但进度仍为不确定状态。`addErrorRequestNum` 不调用进度刷新。

**清空行为由源码确认。** `Clear` 清除列表和计数，但未取消已有工作；后续完成回调仍可写入结果和计数。AutoScan 开关控制新请求监听，也不等于停止已有任务。

源码：`src/main/java/Main/MainPanel.java:102`、`:173`、`:205`。

建议：显示等待、进行中、成功、失败、取消的数量；确定任务总量时展示实际完成比例。明确区分“停止接收新流量”“停止本轮任务”“清空结果”。旧任务不能更新新一轮计数。

验收：全失败也正常结束；停止后不再派发新请求；清空后不出现无法解释的旧结果和 `0 / 1` 类计数。

### 5. 取消后立即再发存在旧任务覆盖新任务的风险

**源码发现，尚未做网络阻塞场景复现。** `cancelRequest` 设置共享 `isCancelled` 并中断线程，立即恢复 Send；再次发送又把共享标志设为 `false`。旧线程退出前可能读取新标志，旧回调或 `finally` 也可能覆盖当前发送状态。

源码：`src/main/java/Main/ManualWafPanel.java:315`、`:3888`、`:4098`。

建议：每次发送持有独立的取消状态和请求快照；所有完成回调验证自己是否仍属于当前任务。取消中状态与真正结束分开。避免把中断线程等同于已终止底层请求。

验收：发送 A → 取消 → 发送 B → A 晚到时，不覆盖 B 的响应、目标、按钮状态和历史归属。

### 6. Follow Redirect 的可见承诺与实际执行不一致

**源码确认。** Manual WAF 的 Burp 发送分支有跳转逻辑，Raw 分支没有使用 Follow Redirect；顶部开关却始终可用。两条发送路径对同一开关表现不同。

Manual Burp 分支还把 `Location: next` 拼成站点根目录下的 `/next`；对于 `/dir/page` 应解析到 `/dir/next` 的情况会得到不同目标。跨主机跳转时复制原有 Cookie / Authorization 等头也需要明确处理。

源码：`src/main/java/Main/ManualWafPanel.java:3950`、`:3990`、`:4118`。Dashboard 另有一套实现：`src/main/java/Main/BypassMain.java:436`。

建议：统一跳转策略和相对 URL 解析。最小版本可在 Raw 模式禁用不支持的选项并解释原因；跨主机跳转不自动携带原站点认证信息，必须保留用户明确选择。展示完整跳转链和实际发送目标。

验收：相对路径、绝对路径、跨站点、303、307/308、Raw/Burp 模式均有明确且一致的行为。

### 7. 差异摘要会把 Body 修改误报为 Header 修改

**已复现。** 原 Body `AAAA` 改为 `BBBB`，请求行和 Body 长度不变，摘要返回 `headers changed`。

原因：摘要只比较请求行及 Body 长度；没有命中时默认判断 Header 改变。

源码：`src/main/java/Main/ManualWafPanel.java:1395`。

建议：分别比较请求行、Header 和 Body 字节；字节数量与内容变化分开。保留二进制比较，避免把所有内容先转换为字符串。

验收：等长 Body 修改正确显示 Body changed；纯 Header 修改显示具体 Header；没有变化时不声称已应用变换。

## 第二批：让操作过程可见

### 请求进入

- 手动右键送入后切换到对应工作区，显示“已加载 GET /admin”。后台 AutoScan 到达时不抢焦点。
- 当前右键操作仅调用 `loadRequest`，没有选中 Manual WAF 页签：`BypassMain.java:665`。
- 空页面说明入口与触发条件。例如 Dashboard 显示“自动扫描未开启；开启后处理新经过 Proxy 的 401/403 响应”。
- 有未发送编辑时，明确提供“保留当前请求”“替换当前请求”，或在后续版本增加多个请求工作页，避免无提示覆盖。

### 点击变换按钮

1. 操作区持续显示作用范围：选区 12 字节 / 整个 Path / Body，以及匹配数量。
2. 必须有选区的工具，在无选区时禁用，并说明需要先选中什么；适合整段执行的工具直接展示默认范围。
3. 点击后在原编辑器突出改变的范围，旁边显示“URL 编码 · 12 → 28 字节”，提供撤销入口。
4. 常规可撤销操作使用非阻断提示；只有需要决定作用范围、强制编码、覆盖内容等情况才弹窗。
5. 相同文字多处出现时，提供选区处 / 全部 N 处 / 第 N 处；选区有效时默认选区处。

现有 Undo/Redo、选区保存和字节处理可以继续使用，不需要重写整个编辑器。

### 发送与接收

- Send 附近展示实际目标、发送模式和将发送的字节数。Auto 选择 Raw 时显示原因，例如“请求头含非 ASCII”。
- 点击 Send 后创建不可变快照。若允许继续编辑，要标记“编辑器内容已有修改，本次响应对应上一版本”。
- 显示发送中与已用时间；取消中和完成分别呈现。响应区域保留前次结果时，明确标记正在等待新结果。
- 到达后展示状态码、耗时、长度差异、跳转链和原因，提供与原响应对比、再次发送、加入历史的入口。
- History 显示目标主机，并明确区分“查看历史”和“载入编辑器”，避免只换右侧响应造成请求/响应配对误读。

## 第三批：补有价值的功能

1. **发送前预览与请求预算。** 自动模式展示变体数量、规则来源和示例，提供本轮上限，便于理解一次操作的影响。
2. **范围与重复任务控制。** 可限定 Burp Scope；同一轮正在执行的重复任务不反复入队，仍允许用户明确重测。
3. **真正的并发上限、停止与重试。** 当前线程池使用 `CallerRunsPolicy`，队列满时提交任务的线程也会执行请求；每个 Proxy 命中又会新建提交线程，因此 Threads 不是严格的全局并发上限。调整线程数时旧池未完成任务仍会继续。先修正计数与上限，再考虑自动限速。源码：`Utils.java:298`、`:322`，`BypassMain.java:1469`。
4. **结果导出与可追溯证据。** 导出请求、响应、目标、规则来源、差异原因和运行选项，方便复现；不要仅导出“成功/失败”标签。
5. **HTTP 方法变异等新规则。** 在任务预算、预览和证据展示稳定后扩展，避免生成更多请求却继续缺少解释。

暂不建议大规模搬入其他工具的全部功能，也不建议为视觉升级更换 Swing 或 Burp 原生编辑器。现有机制足以完成前两批，主要工作是修正状态归属和展示。
